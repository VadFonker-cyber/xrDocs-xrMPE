# Руководство по участию

[English](/.github/CONTRIBUTING.md) | Русский

Спасибо за интерес к xrDocs. Проект принимает исправления документации, новые материалы, улучшения навигации, поиск, стили и инфраструктурные правки.

## Перед началом

- Проверьте открытые Issues и Pull Requests, чтобы не дублировать работу.
- Для крупных изменений сначала создайте Issue с кратким описанием идеи.
- Для небольших исправлений опечаток или ссылок можно сразу открывать Pull Request.

## Локальная разработка

```powershell
npm.cmd install
npm.cmd run dev
```

Сборка перед Pull Request:

```powershell
npm.cmd run build
```

На Windows PowerShell используйте `npm.cmd`, чтобы избежать проблем с execution policy.

## Документация

Каждая страница должна иметь frontmatter:

```md
---
section: Раздел
order: 10
summary: Короткое описание для меню и поиска.
---
```

Правила:

- H1 в Markdown является названием страницы.
- Файлы называются lowercase kebab-case, например `addon-structure.md`.
- Русские страницы лежат в `docs/ru`, английские - в `docs/en`.
- Переводы желательно держать на одинаковых относительных путях.
- Если страница должна иметь стабильное место в меню, обновите соответствующий `init.md`.
- Внутренние ссылки пишите на `.md` файлы, например `[структура аддона](addon-structure.md)`.

## Код

- TypeScript пишется в strict mode.
- Сохраняйте существующую структуру: основная логика в `src/main.ts`, стили в `src/styles.css`.
- Не добавляйте backend-зависимости: проект должен оставаться статическим сайтом.
- Для общих структур предпочитайте явные типы.
- Не коммитьте `dist/`, `node_modules/` и лог-файлы.

## Pull Request

В Pull Request укажите:

- что изменилось для пользователя;
- какие файлы документации или языки затронуты.

CI автоматически запускает production-сборку для Pull Request.

Коммиты должны быть короткими и понятными, например `Add English addon guide` или `Fix search result labels`.
